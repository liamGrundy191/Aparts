SPRINT: PROPERTIES UI   (branch: feat/properties-ui)
=====================================================

GOAL
----
A manager logs in, sees their properties as cards, adds one, opens it,
and manages its units, all without touching Swagger.


USER STORIES
------------
1. As a manager, I can see all my properties as cards, with how many units each one has.
2. As a manager, I can add, edit and delete a property.
3. As a manager, I can open a property and see its units and whether each is vacant or occupied.
4. As a manager, I can add, edit and delete units on a property.
5. As a manager, I always know what's happening: when something is loading,
   when it failed and why, and when my action worked.


SCREENS AND FLOW
----------------
Header nav: [Dashboard] [Properties]
        |
        v
/manager/properties ............ "Add property" button -> form in a dialog
  grid of property cards (placeholder image, name, address, unit count)
  pagination (prev / next, "page 2 of 3")
        | click a card
        v

  - property header: name, address, city, notes      [Edit] [Delete]
  - units table: number | bedrooms | rent | status    [Edit] [Delete] per row
  - "Add unit" button -> form in a dialog

ACCEPTANCE CRITERIA (EVERY TICKET)
----------------------------------
- Loading, empty, error and success states all handled.
- No hardcoded URLs. Use the existing axios client so token refresh keeps working.
- Typed API responses, no `any`.
- `pnpm --filter web lint` and `pnpm --filter web build` pass.


THINGS TO LOOK INTO (THAT'S YOUR JOB)
-------------------------------------
- Query keys: how does the list page learn that you created something?
  Look up "invalidation" in the TanStack Query docs.
- Error codes: the backend sends 400, 404 and 409 for different reasons.
  Which one does each form need to handle, and what should the user see?
- Heads up: check what rentAmount actually looks like in the JSON response
  before you type it or format it. It might not be what you expect.
- Status: a unit's status isn't editable here. Make sure the UI doesn't suggest that it is.
- shadcn here is built on Base UI, not Radix. To make a Button act as a dialog
  trigger, you pass it through the `render` prop, not `asChild`
  (see how ConfirmDialog does it).
